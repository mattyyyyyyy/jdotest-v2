## ADDED Requirements

### Requirement: 原生消费端交易导航必须等待服务端成功
原生 Android 消费端 MUST 在购物车加购、结算建单、支付确认和行车态一键再买的服务端操作成功后再进入依赖该结果的目标页面。失败时 MUST 保留当前页面并展示可重试错误。

#### Scenario: 提交订单成功后进入支付页
- **WHEN** 用户在确认订单页提交已选商品
- **THEN** 系统先创建真实订单并记录订单号与金额
- **AND** 成功后才进入支付页

#### Scenario: 支付确认成功后进入订单页
- **WHEN** 用户在支付页点击「我已支付」
- **THEN** 系统先确认支付并刷新订单
- **AND** 成功后才进入订单页

#### Scenario: 行车态一键再买
- **WHEN** 用户在行车态点击一键再买
- **THEN** 系统创建真实订单
- **AND** 成功后进入支付页

### Requirement: 订单页必须按真实状态展示
原生 Android 订单页 MUST 使用后端订单状态过滤 tab、渲染状态文本、时间线和可用动作。页面 MUST NOT 对所有订单状态显示同一套已完成节点或同一套按钮。

#### Scenario: 已支付订单展示待发货
- **WHEN** 后端订单状态为 `PAID`
- **THEN** 订单页展示「待发货」
- **AND** 不再展示「待付款」

#### Scenario: 订单 tab 过滤
- **WHEN** 用户选择「待付款」tab
- **THEN** 列表仅显示 `PENDING_PAYMENT` 订单

### Requirement: 关键页面跳转必须闭合
原生 Android MUST 挂载 V3 Web 原型对应的 21 条页面路由，且搜索建议、商品详情、购物车、确认订单、支付和订单页之间 MUST 可形成可重复进入与返回的购物循环。

#### Scenario: 搜索建议进入详情
- **WHEN** 用户点击搜索建议商品
- **THEN** 系统记录目标商品
- **AND** 进入对应商品详情页

#### Scenario: 路由静态回归
- **WHEN** 持续回归脚本检查原生路由
- **THEN** 所有声明路由均已挂载
- **AND** 所有页面导航引用均指向已声明路由
