## 一、消费端（原生安卓）— 沿用 JDOTEST，UI 不重画

### ✅ 第一阶段做（可演示路径）

- [ ] 浏览发现：首页（7 场景）/ 分类 / 搜索（含语音）/ 商品详情
- [ ] 交易：加购 / 购物车 / 结算 / 下单 / 立即购买 / 再买一次
- [ ] 支付：车机扫码支付 + 免密一键（Demo mock，不接真实通道）
- [ ] 订单：订单列表 / 详情 / 物流轨迹 / 取消
- [ ] 账号：手机号验证码登录 / 车机扫码登录 / 地址簿 / 个人中心
- [ ] 行车安全：车速 > 5km/h 行车态降级（大按钮、禁键盘、禁视频、再买一次快捷路径）
- [ ] 车机适配：1920×720 / 1920×1080 / 2560×1440 / 2560×1600 横屏，深色为主

> 消费端可演示主链路：**浏览 → 加购 → 下单 → 扫码支付 → 订单查询**，外加一条行车态降级路径。
> UI 以 `mockups/jdo-pencil-v3`（21 屏）为视觉真相，**不重新设计**。

### ❌ 消费端明确不做

- 直播 / 短视频带货（驾驶安全）
- 复杂营销（拼团 / 砍价 / 瓜分红包 / 跨店满减）
- 第三方商家入驻（先自营）
- 真实支付 / 真实物流接入 / 车厂账号 SSO 真实对接（预留接口）
- 多车型 WebView 真机适配（Demo 只验证通用横屏）
- 副驾 / 后排身份识别（统一按驾驶员降级）
- 国际化多语言 / AR/VR/3D 展示

## 二、后台管理（admin · 桌面 Web）— 本次新增 ★

> admin 端是**新增范围**。运行在 PC 浏览器，**不受车机 88px 触控 / 行车态约束**。
> UI 复用 `design-system.md` 的 token / 色板，桌面布局，不另造设计语言。

### ✅ 第一阶段做

- [ ] **admin 登录与权限（admin-auth）**：账号密码登录 + RBAC 角色（超管 / 运营 / 客服 / 财务）+ 操作审计日志
- [ ] **商品管理（admin-catalog）**：商品 / SKU CRUD、7 场景分类维护、上下架、库存调整、图片管理
- [ ] **订单管理（admin-order）**：订单列表 / 搜索 / 详情、改状态、发货、取消、退款审核（与消费端订单状态机同源）
- [ ] **用户管理（admin-user）**：用户列表 / 详情 / 地址、封禁 / 解封、车主认证审核
- [ ] **营销管理（admin-marketing）**：首页 banner、限时秒杀、优惠券（基础）、推荐位配置
- [ ] **履约管理（admin-fulfillment）**：自提点 CRUD、物流轨迹录入 / mock 对接
- [ ] **内容管理（admin-content）**：首页 7 场景配置、商品详情富文本
- [ ] **运营看板（admin-analytics）**：PV/UV、转化漏斗、**车机入口 vs 手机入口订单对比**、行车态切换次数（消费 PRD §H 埋点的可视化）

> admin 可演示主链路：**登录 → 商品上架 → 看到消费端首页出现 → 消费端下单 → admin 订单管理发货 → 消费端看到物流**，打通前后台闭环。

### ❌ admin 明确不做（第一阶段）

- 多租户 / 多商家后台（与消费端"先自营"一致）
- 复杂工作流审批（多级审批、工单流转）
- 财务对账 / 开票系统（仅占位，不做真实财务）
- BI 自助分析 / 自定义报表（看板用固定几张图）
- admin 端移动 App / 响应式手机适配（桌面优先）
- 真实第三方物流 / 短信 / 推送服务商对接（mock）
